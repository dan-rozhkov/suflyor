# Auto для Codex

Выполни задачу пользователя по workflow проекта до проверенного результата.
Этот скилл адаптирует команду Claude Code для Codex.

## Исходный workflow

Перед выполнением прочитай [исходную команду auto](../../../.claude/commands/auto.md) целиком.
Она содержит шаги, команды проверок, формат отчёта и правила очистки.
Применяй её с заменами ниже. При расхождении используй эту адаптацию.
Не изменяй исходную команду при выполнении задачи.

Запрос после `$auto` или `/auto` заменяет `$ARGUMENTS`.
Необязательный `notion:<URL>` указывает страницу для обновления.
Просьба установить или изменить скилл не запускает его workflow.

## Разрешения и границы задачи

Работай без повторных подтверждений уже разрешённых действий.
Явный запуск полного workflow включает commit, push в main и отчёт в Notion для указанной задачи.
Если скилл выбран автоматически, проверь, разрешил ли пользователь эти внешние действия.
Сам выбор скилла не предоставляет разрешение на публикацию.
Ограничения пользователя, среды и системные инструкции сохраняют приоритет.
Не обходи sandbox. При ограничении доступа используй штатный механизм разрешений среды.
Продолжай независимую разрешённую работу при недоступности обязательного доступа.
Сообщай о заблокированном шаге прямо. Не объявляй весь workflow завершённым при пропущенных обязательных шагах.

## Замены инструментов Claude Code

| Исходный инструмент | Действие в Codex |
| --- | --- |
| `Skill` | Прочитай соответствующий доступный `SKILL.md` и выполни инструкции. |
| `superpowers:brainstorming`, `superpowers:writing-plans` | Используй доступный подходящий скилл. Если его нет, сам составь план и обозначь существенные допущения. |
| `Agent`, `model: "sonnet"` | Используй инструменты субагентов Codex с наследуемой моделью. Не запрашивай недоступную модель Sonnet. |
| `/code-review` | Используй доступный скилл ревью или отдельного субагента для ревью фактического diff. Если делегирование недоступно, проверь diff сам и укажи это. |
| `superpowers:receiving-code-review` | Проверь каждое замечание по коду и исправь подтверждённые проблемы. |
| `superpowers:verification-before-completion` | Прочитай результаты проверок и коды завершения до заявления о готовности. |
| `Bash` | Используй инструмент запуска shell-команд с явным `workdir` или `git -C`. |
| `Read` для PNG | Используй инструмент просмотра локальных изображений. |
| `$SCRATCH` | Создай отдельную временную папку через `mktemp -d` в разрешённом временном каталоге. |
| `notion-*` | Найди подключённые инструменты Notion по назначению. Проверь их реальные схемы перед вызовом. |

Разделяй независимые задачи по непересекающимся файлам.
Передавай каждому агенту абсолютный путь worktree, границы правок и команды проверок.
Запрещай агентам менять основной checkout и выполнять git-операции.
Если субагентов нет, выполни работу самостоятельно и укажи ограничение.

## Инварианты проекта

- Это один публичный git-репозиторий. Создавай worktree рядом с ним: `wt-auto-<slug>`.
- Ключи живут в Infisical: `infisical run --env=dev -- <команда>`. Не печатай их, не записывай на диск и не передавай агентам.
- Транскрипты встреч, данные клиентов и записи звука в репозиторий не попадают. Примеры только вымышленные.
- Не снимай весь экран. Снимай только страницу приложения.
- Продукт один: сайт в `src/` и Cloudflare Worker. Electron и Swift в проекте нет.
- Используй отдельный свободный порт с `strictPort`.

## Проверки и публикация

Сохрани проверки исходного workflow: `npm run typecheck`, `npm test`, `npm run build`. Линтера в проекте нет.
Запускай каждую проверку отдельно. Сохраняй лог и фактический код завершения.
Не используй `npm test -- run`. Укажи число файлов, тестов и пропусков.
Не снижай пороги проверок ради успешного результата.

Перед коммитом проверь diff и добавь в index только перечисленные пути задачи.
Не добавляй строки атрибуции Claude из исходника.
Соблюдай правила атрибуции репозитория. Не выдумывай автора или модель.
Выполняй fetch, rebase и push отдельными вызовами.
При конфликте разрешай только понятные изменения в рамках задачи.
После изменения базы повтори проверки.
Проверь, что `origin/main` является предком `HEAD`, до обычного push `HEAD:main`.
Не выполняй force push.

## Скриншоты и Notion

Снимай проверенную опубликованную версию по правилам исходника.
Просмотри каждый PNG перед добавлением в отчёт.
Найди существующую страницу по URL или `auto-slug`, прежде чем создавать новую.
Сохрани формат отчёта и приватный режим страницы из исходника, если подключённый API его поддерживает.
Не заявляй приватность без подтверждения API или настроек доступа.
Не выдумывай методы загрузки файлов и параметры Notion.
Если нужного инструмента нет, сохрани локальный Markdown-отчёт и PNG в папке результатов.
Укажи, что публикация отчёта заблокирована, и назови недостающий доступ.
Не удаляй результаты, необходимые для последующей публикации.

## Завершение

Удаляй только созданный этой задачей чистый worktree после подтверждённого push.
Перед удалением ветки проверь, что её коммиты доступны в `origin/main`.
Сохраняй грязный worktree и непубликованные коммиты.
В ответе укажи результат, SHA, проверки, ссылку на отчёт и незавершённые шаги.
